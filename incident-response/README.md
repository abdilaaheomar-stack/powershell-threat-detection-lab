# Incident Response Case Study

## Investigation of Suspicious PowerShell EncodedCommand Activity

### Executive Summary

During routine security monitoring activities, the Security Operations Center (SOC) identified suspicious PowerShell execution activity originating from a Windows workstation. Detection alerts generated by custom Wazuh correlation rules identified the use of encoded PowerShell commands commonly associated with adversary tradecraft and post-exploitation activity.

The incident was escalated for investigation due to the elevated risk associated with PowerShell abuse, command obfuscation techniques, and potential execution policy bypass attempts.

The investigation focused on determining:

* Scope of activity
* User involvement
* Potential compromise indicators
* Persistence mechanisms
* Lateral movement attempts
* Impact to organizational assets

# Initial Triage

The analyst reviewed the alert and identified the following suspicious command line activity:

```powershell
powershell.exe -EncodedCommand SQBFAFgA
```

The use of encoded PowerShell commands is frequently observed during:

* Malware execution
* Living-off-the-Land techniques
* Adversary command obfuscation
* Remote payload execution
* Credential harvesting operations

Because encoded commands obscure the true execution intent, additional analysis was required.

---

# Investigation Activities

## Step 1 – Validate Alert

Reviewed Sysmon Event ID 1 process creation logs.

Collected:

* Executable path
* Parent process
* Command line arguments
* User account
* Hostname

Finding:

PowerShell launched from an interactive user session.

Risk Level:

Medium

---

## Step 2 – Parent Process Analysis

Reviewed process lineage.

Process Tree:

```text
explorer.exe
 └── powershell.exe
```

Observation:

The process originated from a user desktop session rather than an automated system task.

No evidence of Office macro execution or browser exploitation was identified.

---

## Step 3 – Command Analysis

The encoded command was decoded within a controlled analysis environment.

Finding:

The decoded command executed a benign system query.

No external network connections were observed.

No evidence of payload retrieval was identified.

Risk Level Reduced:

High → Low

---

## Step 4 – Persistence Review

Analysts reviewed:

* Scheduled Tasks
* Registry Run Keys
* Startup Folders
* Windows Services

Finding:

No persistence mechanisms identified.

---

## Step 5 – Lateral Movement Investigation

Reviewed:

* SMB Activity
* Remote PowerShell Sessions
* Authentication Logs
* Administrative Shares

Finding:

No lateral movement indicators observed.

# Containment Actions

Although malicious activity was not confirmed, the following actions were performed:

* User account reviewed
* Endpoint scan completed
* Security logs preserved
* Detection rule validated
* Event documented

No isolation was required.

---

# Root Cause Analysis

The PowerShell command originated from a cybersecurity testing activity conducted within a controlled lab environment.

The behavior was intentionally generated to validate detection logic and alert generation capabilities.

The detection successfully identified the activity as designed.

---

# Remediation Activities

The following improvements were recommended:

## Detection Enhancements

* Expand PowerShell telemetry collection
* Enable Script Block Logging
* Enable Module Logging
* Increase command-line visibility

## Monitoring Improvements

* Add additional Wazuh correlation rules
* Improve behavioral analytics coverage
* Expand MITRE ATT&CK mapping

## Security Controls

* Restrict unnecessary PowerShell usage
* Implement application control policies
* Review execution policy enforcement

---

# Lessons Learned

This investigation demonstrated the importance of:

* Process creation monitoring
* PowerShell command-line visibility
* SIEM correlation capabilities
* Structured incident response procedures

The detection pipeline successfully identified suspicious activity, provided actionable telemetry, and enabled rapid analyst validation.

---

# Analyst Conclusion

The investigation concluded that the activity represented authorized security testing rather than malicious behavior.

No compromise was identified.

The detection logic performed as expected and provided confidence in the organization's ability to identify suspicious PowerShell execution activity in the future.
